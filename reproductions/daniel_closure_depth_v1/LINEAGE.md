# Experimental lineage behind this reproduction

The finite reproduction in this folder is intentionally not presented as the whole empirical claim. It isolates one exact mechanism from a longer sequence of experiments across the `heathsanchez` research repositories.

## 1. MathGraph: residuals become persistent routing evidence

The older MathGraph work established the controller pattern:

```text
attempt -> externally checked outcome -> residual/obstruction
        -> retained law/routing state -> changed next search
```

The important trust discipline was already present: route scores and learned constructor preferences can guide search, but only external verification or finite checking can promote a claim.

## 2. Triskelion V54: two-generation developmental discoverability

Repository: `heathsanchez/triskelion`

Relevant harness:

```text
experiments/METALOGIC_TWO_GENERATION_COMPOUNDING_V54.py
```

Historical fix commit:

```text
2dd5f41b6c7cec1004b8deaee4f976dd2a9ed21c
```

V54 contains the strongest early operator-level compounding pattern:

- a first capability `O1` is outside the old permutation/reordering closure;
- the later target has two defects;
- under the frozen one-new-rewrite budget there are zero cold verifier-surviving repairs;
- reusing `O1` changes the residual;
- a unique second capability `O2` then becomes discoverable;
- `O1` alone is insufficient;
- `O1 + O2` succeeds;
- ablating `O1` while retaining `O2` restores failure.

V54 therefore supports **developmental discoverability**: retained verified capability changes what later repair can be found under the same bounded search protocol.

It does not establish that the raw token-emission meta-language was unable to *spell* `O2` before `O1`.

## 3. Quotient identity: literal operator is not the right unit

Subsequent Triskelion experiments tested whether a constructed capability should be identified with a literal implementation.

The emerging result was that different literals can collapse under transformations already expressible in the old language. Capability identity is therefore more naturally indexed to the current closure:

```text
[Delta]_(G_t)
```

rather than to one source-code spelling of `Delta`.

The finite reproduction makes this exact in a tiny world: two different positional rewrites have empty literal intersection but the same class once position is quotiented by the old transport action.

## 4. Scope, counterevidence, and revocation

The Triskelion natural-code line separately showed that capability acquisition and applicability are not the same claim.

A capability can be causally useful and transferable while its learned activation condition is too broad. Later counterevidence can invalidate every admissible refinement in the frozen scope grammar, forcing `REVOKE` instead of permanently retaining a locally successful repair.

The finite reproduction includes a minimal exact version of that lifecycle, but the natural-code experiments are the stronger evidence for the acquisition/applicability separation.

## 5. Specimen V132: real one-generation constructibility expansion

Repository: `heathsanchez/triskelion`, external substrate `heathsanchez/specimen`.

Result commit:

```text
e32af302b91da1e5837f08d70baff436eea2ce83
```

V132 is materially stronger than the token-world reproduction because it concerns a real Lean metaprogramming constructor substrate.

After a sequence of prospective discriminators and rejected over-broad mechanisms, the admitted `K5` rule preserved a proper function application during conclusion linearization only when:

1. every free-variable dependency occurs in relation-input positions; and
2. that exact application occurs in the inferred dependent type/family of an output-position argument.

The frozen result was:

```text
K2 FAIL
-> K2 + K5 PASS
-> full protected Specimen suite PASS (137/137)
-> remove K5 while retaining K2
-> FAIL
```

The supported bounded claim in that result is a **causal expansion of constructibility** in a pinned real Lean metaprogramming system.

## 6. Specimen V133: the acquired capability exposes a new residual

Result commit:

```text
804feb7600bba9604e7b8467e0deb6384572e694
```

Exact admitted `K2 + K5` was replayed unchanged on the harder known Strata target.

It did **not** solve the target. Instead, the dominant failure changed:

- the earlier hidden computed-family / universe-style obstruction was no longer primary;
- the derivation progressed farther;
- a new residual appeared around typeclass synthesis over symbolic family parameters.

This is important developmentally because the admitted first representation change did not simply make the old problem easier; it exposed a qualitatively different next obstruction.

## 7. V134: prospectively frozen next discriminator

Precommit:

```text

```

V134 freezes a new controlled family, unrelated to Strata, to test whether a target-fixed family parameter remains unnecessarily symbolic at the point of instance synthesis.

No new repair is allowed inside V134. The purpose is only to decide whether the new V133 residual reproduces in a controlled setting before a second mechanism is designed.

At the point this reproduction package was assembled, the repository contained the V134 precommit but no later V134 result in the audited history.

## 8. Why the finite reproduction exists

The exact token-world reproduction is therefore not intended to prove the strongest developmental claim. It does three useful things:

1. makes closure-relative capability identity inspectable in a few hundred lines;
2. cleanly separates developmental discoverability from raw meta-language constructibility;
3. falsifies the temptation to upgrade a V54-style result into strict second-order constructibility.

The open research target is stronger:

```text
G0 --verified residual--> G1 = G0 + K1
G1 --new residual-->     G2 = G1 + K2
```

with evidence not merely that `K2` becomes useful or discoverable after `K1`, but that `K1` causally changes the constructor substrate so that a class of `K2`-type capabilities becomes constructible that was genuinely unavailable before.

That is the point at which a categorical/formal account of the changing capability structure becomes especially interesting.
