# Closure-Relative Developmental Depth V1

This is an exact finite capstone built **after** auditing the historical MathGraph/Triskelion programme. It deliberately separates claims that earlier experiments can otherwise blur:

1. closure expansion;
2. literal operator identity vs closure-relative capability identity;
3. source-distinct transport and causal ablation;
4. verifier-dependent two-generation **discoverability**;
5. strict two-generation **constructibility**.

The finite token world is a model/testbed, not itself a novelty claim.

## Why this test exists

The repository history already contains stronger real-world ingredients than a toy partition-refinement demo:

- V54: two-generation operator-level discoverability (`O2` has zero cold one-rewrite survivors and becomes discoverable after `O1`);
- quotient/capability-identity work: literal implementations can collapse under transformations already present in the old closure;
- scope/revocation work: a useful capability can be admitted, transferred, ablated, and later revoked by counterevidence;
- V124–V132 on Specimen: residual-guided representation search isolates and admits a real constructibility-changing mechanism with protected-suite validation and causal ablation;
- V133: that admitted mechanism exposes a deeper residual but does not itself close it.

So this capstone asks a sharper question: **does the strongest second-order claim actually follow?**

## Exact model

Programs are four-token states. The old language can cyclically transport positions but cannot change token values. Token multiset is therefore an exact invariant of the old closure.

The generic construction meta-language emits one-position token rewrites. Literal rewrites at different positions are quotiented by the old transport action, producing a closure-relative capability class `src -> dst`.

### Generation 1

Two source-distinct cases require the same semantic repair at different positions.

- Literal repair identity has empty intersection.
- After quotienting by old transport, both induce the unique class `LT -> LE`.
- An alternate constructor presentation recovers the same class.
- All 24 bijective renamings of the four role tokens recover the same class after mapping back.
- A frozen scope grammar identifies `context == if` as the unique minimal safe scope.
- A held-out position is solved by quotient transport, while literal-identity transfer fails and ablation restores failure.

### Generation 2

A held-out target contains two independent defects: `LT -> LE` and `AND -> OR`.

Under the frozen budget of **one new capability class**, cold search has zero verifier-surviving candidates. Reusing admitted `O1 = [LT -> LE]` first changes the residual; one-new-class search then identifies `O2 = [AND -> OR]`.

The script exhaustively checks that the final target is outside the semantic closure generated by old transport + O1, so O2 is genuinely closure-expanding relative to `G1`. Final success requires both classes; either targeted ablation restores failure.

Cold exhaustive two-rewrite reconstruction considers 784 literal pairs. Warm full one-rewrite audit considers 28 candidates: 28x search compression in this finite world.

Later counterevidence lies inside the admitted observable scope. Under the frozen context-only scope grammar no valid refinement remains, so the lifecycle decision is `REVOKE` rather than fossilizing a local success.

## The important falsification

The capstone audits a stronger claim separately:

> Was O2 syntactically unconstructible in the raw generic meta-language before O1 existed?

**No.** The literal `AND -> OR` primitive is already expressible in the raw meta-language before O1. What changes after O1 is whether that primitive becomes a verifier-surviving/admissible continuation under the one-new-class developmental protocol.

Therefore the correct result is:

```text
core_verdict = PASS_DISCOVERABILITY_DEPTH
overall verdict = PARTIAL_STRICT_CONSTRUCTIBILITY_NOT_ESTABLISHED
```

This prevents a V54-style developmental-discoverability result from being silently upgraded into the stronger claim that the first learned capability changes the raw meta-language of what can be constructed next.

## What would close the remaining gap

A strict second-order constructibility result needs a future protocol where, before O1, O2 is not merely unsuccessful but **cannot be formed/typechecked/generated by the frozen constructor substrate**, while after installing O1 the constructor substrate gains a lawful new construction path that produces O2. The test must avoid making this true merely by defining an O2 constructor that takes O1 as a hard-coded argument.

The real Specimen line is the right substrate for that next test because it already demonstrates one-generation causal constructibility expansion and a subsequent changed residual without pretending the second generation is solved.

```bash
python experiments/closure_relative_developmental_depth_v1/run.py
```
