# Ethereum Crystal v4

This is the first Ethereum experiment in this branch that uses the actual Crystal developmental protocol rather than merely applying MSI terminology.

Protocol:

```
insufficient interface
→ verified protected-consequence conflict
→ residual-conditioned separator search
→ capability promotion
→ retry
→ causal ablation
→ source-distinct held-out task
→ reuse promoted capability at zero reacquisition cost
→ acquire only the new residual distinction
→ compound interfaces
```

The frozen feature family is `slot/read/post/pre`; it cannot be changed after target outcomes are observed.

Generation 1 discovers `slot` because it strictly reduces the dependency obstruction. Generation 2 uniquely closes the dependency target with `read`. Removing either promoted distinction restores failure.

The held-out target is reconstruction, not dependency analysis. It reuses the already promoted `slot` distinction for free and acquires only `post`; `slot` is not rediscovered. The resulting retained capabilities compose into an interface that closes both protected consequence families.

**Boundary:** exact finite EIP-7928 semantic abstraction and frozen refinement grammar. This warrants a bounded developmental event and source-distinct capability reuse; it does not warrant universal representation invention or full-EVM optimality.
