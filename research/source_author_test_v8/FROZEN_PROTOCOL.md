# V8 — author-native verifier/test-entrypoint authority from source documentation
Date: 2026-10-20 NZ. Status: CANDIDATE before prospective source exposure.

## Objective
A real source-authoritative test runner is sometimes *not* the default pytest collection. On exposed `trentm/python-markdown2`, generic pytest collected 29 cases, while author-documented original driver ran 276. That observation is source-native TRAINING [GREEN #39355471746](https://github.com/metalogiclabs/mathgraph/actions/runs/39355471746); V7 semantic obligation acquisition remained UNKNOWN and must never be retroactively promoted.

Test whether a source-neutral, fixed, finite observation operation can propose a verifiable **author-native test-entrypoint authority** from a new repo without reading its source behavior, and whether it changes the measured original-native verification scope versus a common generic pytest baseline. This is a source-verifier-authority family, **not** a new meaning theorem and **not** autonomous method invention.

## Pre-exposure frozen method and fair comparator
- `propose.py`: Python 3.12 stdlib only, examine exactly the frozen list of public test README / CONTRIBUTING / root README files, each max 100 KB. Require unambiguous documented tests/suite context and a **restricted, shell-operator-free** `python[3] test_file.py`, `python -m pytest` or `python -m unittest` entrypoint. Require the referenced native script exists in its original directory, not dynamically downloaded source. Tokenize with `shlex`; refuse unsafe/unrecognized flags or nonlocal scripts. Retain exact original source-document SHA256, quoted line, line number, cwd and command argv. Multiple differing eligible commands => `UNKNOWN_AMBIGUOUS_AUTHOR_RUNNER`. No source test/implementation execution to propose authority.
- Separately authored conventional expert-rulebook `expert_reference` receives **identical** public documentation and source metadata and can select the same restricted original command. It is not a blinded human expert, and rulebook equality is **TIE only if an authentic author command executes**; zero-zero no-author-runner is INCONCLUSIVE, not a triumph.
- `evaluate.py`: before native execution both sealed proposals are SHA-bound to an immutable source commit. Execute **default `python -m pytest -q` and the discovered source-authoritative command** in isolated identical checked-out source (different cwd allowed only when declared by author). Preserve raw outputs, exit status, elapsed runtime and actual count from summary; if command unsupported, exit nonzero, no collected cases or timeout, give explicit UNKNOWN/REJECTED_BOUNDED; no artificial GREEN.
- **No superset inference from counts alone.** A larger author-run count is not evidence of individual test identity inclusion without matching node IDs. Cases tagged known failure can be explicitly excluded by the original prescribed script and must be disclosed.
- For an admitted author command, physically remove the **one cited source documentation line** only in the ephemeral checkout (test code unchanged), rerun `propose.py`, show whether and precisely which authority still survives, then byte-exact restore and recheck original proposal/hash. If another documented entrypoint remains, the warrant persists only through that still-existing authority. Do not delete actual author tests.
- No source-specific repair or secret/network-adapter write after results. Error recovery is separately labeled apparatus and cannot substitute a new source. Do not claim G2/L7, automatic grammar invention, general user-intent fidelity or human baseline advantage.
- **Pre-exposure synthetic + EXPOSED markdown2 training** must be GREEN before selection. Only after source-independent exact method/protocol commit may repository metadata and ROS be queried to choose a future.
