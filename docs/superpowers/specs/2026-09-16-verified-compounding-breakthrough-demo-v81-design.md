# V81 Verified Compounding Intelligence Breakthrough Demo — Design

Date: 2026-09-16
Branch: `verified-compounding-breakthrough-demo-v81`
Status: design approved at approach level; implementation pending spec review

## Purpose

Build one self-contained, reproducible GitHub Actions demo that assembles the strongest completed MathGraph evidence into a single verifier-gated developmental chain and then runs a new fresh prospective end-to-end developmental experiment.

The demo is not a marketing montage. It must emit one machine-readable manifest whose claims are bounded by exact gates, hashes, artifacts, causal witnesses, exhaustive optima where claimed, and explicit negative/unknown outcomes where a stage does not support a stronger conclusion.

The top-level research thesis is **Verified Compounding Intelligence**. The directly demonstrated mechanism is **Verifier-Gated Development**.

## First-class objects

### Verified Capability Block

A reusable unit of admitted capability:

```text
VerifiedCapabilityBlock = {
  id,
  applicability,
  action,
  certificate_or_verifier_boundary,
  provenance,
  dependencies,
  scope,
  causal_evidence,
  persistence_hash
}
```

The demo may adapt existing retained graph nodes / Lawbook artifacts into this schema. It must not imply every historical artifact was originally serialized in this exact form.

### Verified Obstruction

A certificate that a previously sufficient state is insufficient under a declared lawful extension:

```text
VerifiedObstruction = {
  id,
  prior_state,
  prior_scope,
  extended_scope,
  exact_global_old,
  persistent_value_new,
  exact_global_new,
  residual,
  provenance
}
```

A residual is development pressure, not truth.

### Verified Development Transition

An admitted state change:

```text
VerifiedDevelopment = {
  from_state,
  proposal,
  verifier,
  delta,
  admitted,
  to_state,
  causal_witnesses,
  exact_optimality_status
}
```

Learning orders proposals. Verification has epistemic authority.

## Demonstration architecture

The demo has two evidence lanes that join into one final manifest.

### Lane A — historical authoritative evidence replay/validation

This lane does not relabel historical experiments as fresh. It validates their pinned claims, authoritative hashes, and evidence artifacts.

Stages:

1. **Trust boundary / terminal contract**
   - Re-run release and invariant checks.
   - Demonstrate advisory signals cannot promote truth.
   - Accepted terminal forms remain `VERIFIED_PROOF`, `FINITE_COUNTERMODEL`, or `NAMED_OBSTRUCTION`.

2. **Real SAIR verified-memory evidence**
   - Validate the canonical official SAIR Stage 2 evidence pack metadata and replay contract.
   - If raw real-corpus inputs are not present, mark this as `AUTHORITATIVE_EVIDENCE_VALIDATED`, not `FRESH_REAL_CORPUS_RERUN`.
   - Preserve the existing strict-admission and zero-contamination boundaries.

3. **V66 causal persistent capability recurrence**
   - Validate the authoritative V66 developer/evidence identifiers and causal recurrence claim.
   - Record this as evidence that retained verified capability can causally help later external tasks.

4. **V71 negative forced-development lesson**
   - Record the calibration result that forced change can harm utility.
   - This licenses `ABSTAIN` / `REUSE`, rather than unconditional modification.

5. **V72 learned proposal ordering under exact verifier gating**
   - Validate held-out source-ID transfer and exact local-optimum certificates.
   - Learning is credited only with fewer checks / proposal ordering, not truth.

6. **V73 prospective six-operation transfer**
   - Validate freeze-before-generation integrity and globally bounded claim.

7. **V74 exact depth-2 global exhaustion**
   - Validate exhaustive fixed-budget global optimality.

8. **V75 lawful depth-3 obstruction**
   - Validate that a larger consequence language makes previously global-optimal states insufficient.

9. **V76 minimal verifier-horizon repair**
   - Validate all depth-3 residuals repaired with unchanged budget and unchanged one-swap action language.

10. **V77 prospective full developmental cycle**
    - Validate prospective `sufficiency -> obstruction -> minimal repair -> new sufficiency` on fresh seven-operation sources.

11. **V78 autonomous reuse-vs-expand controller**
    - Validate autonomous per-source branching between `REUSE_STATE_UNDER_EXTENDED_VERIFIER` and `EXPAND_VERIFIER_ONLY` through horizon 4.

12. **V79 action-language obstruction calibration**
    - Record the negative result honestly: no certified one-swap obstruction found on the selected depth-5 hard sources.
    - This is evidence *against* unnecessary action-language widening in that bounded calibration set.

13. **V80 prospective deep-horizon action invariance**
    - Validate the completed authoritative result:
      - 6 fresh nine-operation sources
      - horizons 2 through 6
      - 18,205 exact fixed-budget states enumerated
      - 345 total obstruction units exposed
      - 345 total recovered
      - 8 `REUSE` decisions
      - 16 `EXPAND_VERIFIER_ONLY` decisions
      - 0 action-language expansions required
      - 28 causal new-reach examples
      - learned verifier checks 851 vs generic 1,054
      - final verdict `PASS_PROSPECTIVE_DEEP_HORIZON_ACTION_INVARIANCE_V80`
      - protocol SHA `9eb6155def95e3a6cedc324ed31decc49434e1956fe54da730703c36d2b3be2e`
      - developer SHA `82a884cf7b233b305f5fe3f7ec7f79e652cfd63ea0ad9e370bf0f53acbf92eed`

### Lane B — new V81 prospective breakthrough experiment

V81 must be fresh relative to all previous synthetic streams.

Before generating any V81 source, freeze and hash:

- learned proposer weights / developer hash;
- retained budget;
- action grammar;
- consequence-layer generation algorithm;
- horizon range;
- source generator seed and grammar boundary;
- all pass/fail gates;
- warm/cold comparison rules;
- exact-optimality audit rules.

The new source grammar should be structurally outside the previously opened synthetic streams (for example ten-operation source laws, assuming implementation confirms the prior maxima).

For each fresh source:

1. Start from the declared cold capability state.
2. Develop under the current verifier until exact fixed-budget global sufficiency is certified.
3. Persist/serialize the admitted capability state and restart it.
4. Reveal exactly one lawful larger consequence horizon only after the prior global certificate.
5. Construct a `VerifiedObstruction` iff the persistent state is below the new exact global optimum.
6. Let the controller choose `REUSE` when residual = 0, otherwise attempt `EXPAND_VERIFIER_ONLY` using the same action grammar.
7. Require every admitted move to have strict positive exact verifier delta.
8. Exhaustively certify the endpoint against the exact global fixed-budget optimum.
9. Continue across the frozen horizon boundary.
10. Run explicit warm-vs-cold economics on later horizons / later fresh sources using equal verifier semantics and equal allowed action language.

## Compounding test

The final demo must distinguish accumulation from compounding.

At minimum it will report:

```text
cold_checks_to_certified_endpoint
warm_checks_to_same_certified_endpoint
check_savings = cold - warm
```

where warm may use only previously admitted persistent capability / frozen learned ordering, and both paths must terminate at the same exact globally certified endpoint or the comparison is invalid.

The strongest supported V81 compounding claim requires all of:

- same endpoint quality under exact verifier;
- no extra truth access for warm;
- warm uses fewer verifier checks on at least one predeclared comparison;
- aggregate warm checks are not worse than aggregate cold checks;
- retained capability or learned developmental structure is causally responsible for at least one saving, established by deletion/restoration or an equivalent exact counterfactual;
- no contamination or label leakage.

The demo must label the result `ACCUMULATION_ONLY`, `VERIFIED_COMPOUNDING_SIGNAL`, or `FAIL` according to frozen gates. It must not force a compounding verdict.

## Top-level verdicts

The workflow has separate verdicts rather than one hype label:

1. `TRUST_BOUNDARY_PASS`
2. `HISTORICAL_LINEAGE_VALIDATED`
3. `FRESH_DEVELOPMENTAL_CYCLE_PASS`
4. `AUTONOMOUS_REUSE_EXPAND_PASS`
5. `GLOBAL_OPTIMALITY_GATES_PASS`
6. `VERIFIED_COMPOUNDING_SIGNAL` or `ACCUMULATION_ONLY`

A synthetic top-level `PASS_VERIFIED_COMPOUNDING_INTELLIGENCE_BREAKTHROUGH_DEMO_V81` is allowed only when all mandatory trust/development gates pass and the frozen compounding gate returns `VERIFIED_COMPOUNDING_SIGNAL`.

If development passes but compounding economics do not, emit a bounded verdict such as `PASS_VERIFIED_DEVELOPMENT_DEMO_V81_ACCUMULATION_ONLY`.

## Failure semantics

- Missing authoritative historical artifact: fail historical validation, do not substitute memory.
- Historical source unavailable but immutable identifiers are present in repo: report `UNVERIFIED_IN_THIS_RUN`; do not silently pass.
- Fresh endpoint below exact global optimum: fail that source.
- One-swap local optimum below global: emit `ACTION_LANGUAGE_EXPANSION_REQUIRED`; do not widen action language inside V81.
- No residual under a larger horizon: `REUSE`; do not force change.
- Warm path loses endpoint quality: compounding comparison invalid/fail.
- Warm does not reduce cost: report accumulation/neutral, not compounding.
- Failed search never promotes TRUE.

## Testing

Implementation must include:

- unit tests for the three first-class schemas;
- deterministic protocol-hash test;
- historical-stage identifier validation tests;
- no-leakage test proving V81 source generation occurs only after protocol freeze;
- replay tests for every newly generated consequence node;
- exact global enumeration tests on every claimed global endpoint;
- warm/cold equality-of-endpoint test;
- ablation/counterfactual test for at least one compounding saving;
- artifact-manifest hash self-check;
- workflow-level failure when any mandatory scientific gate fails.

## Non-goals / claim boundary

V81 will not claim:

- AGI;
- universal self-improvement;
- unbounded adequacy;
- that one-swap actions are universally sufficient;
- that synthetic source-law transfer is identical to natural-world transfer;
- that advisory memory verifies truth;
- that all historical experiments are rerun fresh inside V81.

The bounded breakthrough claim is:

> A verifier-gated developmental system can turn admitted reasoning structure into persistent reusable capability, certify when that capability remains sufficient, produce exact obstructions when a lawful consequence extension makes it insufficient, admit only strictly verified repairs, autonomously choose reuse versus minimal verifier expansion, and—if the frozen warm/cold gates pass—show that prior admitted capability reduces the verifier cost of reaching later equally certified capability.
