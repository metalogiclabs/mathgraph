# MathGraph Check × L4YAML — source-bound semantic continuity

## Objective

Make a reusable *outside-the-upstream-repository* check of whether a pinned L4YAML commit exhibits the 13-case alias-rebinding behavior, and whether that observation is still authorized by its original source and evidence. The present bounded residual is a five-case native semantic mismatch. Do not present it as a Lean theorem about all YAML inputs, nor as a JPL endorsement.

## Evidence and trust boundary

- Independently verify the entire 13-case log with the retained native verifier, fixed literal expected trees, ruamel.yaml oracle snapshot, zero stderr, exact Lean release and clean committed source.
- Distinguish native computational observations from documentary source identity and from any permission to merge/deploy. A receipt is not a proof without replay and source qualification.
- The warrant engine is a closure operator over **already independently admitted** receipts, not a source authenticator. The executable CLI therefore runs the pinned external verifier first; an unqualified report must never receive an active semantic route.
- An observed mismatch yields a bounded nonconformance report, not `FINITE_COUNTERMODEL` or a universal `REJECTED` mathematical claim. Cycles remain outside the acyclic verdict.
- For any new commit, replay the source-native probe. A fixed code blob in another SHA is not by itself a new run. Stale source or withdrawn oracle/native/verifier evidence closes the corresponding route to `UNKNOWN` while preserving unrelated claims.

## Minimal experiment

1. Freeze a specific 40-hex L4YAML integration SHA, source paths, Lean toolchain and oracle fixture.
2. Build native Lean modules; capture 13 JSONL cases and stderr without changing upstream.
3. Run strict verifier; separately compose documentary, behavioral, control and decision states via `warrant_resolution`.
4. Assert adversarial tests for stale SHA, tampered/incomplete log, evidence removal and bounded repair. Publish only an owned GitHub Actions report and attach native evidence as an artifact.

## Acceptance

One MathGraph-owned workflow, one source-bound JSON report, retained raw artifacts, and tests demonstrating that source identity, empirical semantic findings and decision authority cannot be conflated. There is no upstream modification, installation or outreach.
