# MathGraph Living Knowledge Network Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a protected-preview MathGraph release candidate where a visitor or independent agent can search a real source-pinned Mathlib catalogue, inspect permanent declaration-occurrence pages and typed non-logical relationships, reproduce existing bounded evidence, and understand the qualified Resolve withdrawal example without any source-index result being promoted to mathematical truth.

**Architecture:** Keep the existing Astro static site, qualified records, capability contracts, and presentation-only object projection model. Add one bounded Mathlib `v4.34.1` source catalogue generated by a Lean-native extractor, canonicalized by a small Python publisher, and checked by a separately implemented standard-library consumer. Extend the current object/search/map surfaces with source occurrences and bounded neighbourhoods; reuse the existing precomputed Resolve scenarios for the signature interaction. Add no database, backend, graph service, arbitrary importer, proof-execution endpoint, MCP server, or browser-side verification authority.

**Tech Stack:** Python 3.11+, pytest, Lean/Mathlib `v4.34.1`, JSON Schema Draft 2020-12, Astro 7.3.8, TypeScript 6.0.3, Vitest 5.0.3, Playwright, static SVG/HTML, GitHub Actions, Vercel protected previews.

**Spec:** `docs/superpowers/specs/2026-10-12-living-knowledge-network-design.md`
