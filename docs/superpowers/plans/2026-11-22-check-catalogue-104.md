# Retained failure checks and the 104-prompt catalogue

## Authorized objective

Improve Check directly against the known audit witnesses. External operator
participation is not a prerequisite. Add EA01 per-case agreement and EA03
refusal/apparatus distinction, run them alongside the retained XML and JUnit
status profiles, and account for every catalogue prompt in each invocation.

## Contract

- Preserve catalogue r2 IDs 1–104, exact names and prompts. These remain
  CANDIDATE_PROMPT search topics; a checked facet cannot close a whole topic.
- Run every retained local profile by default on the same resolved Git commits.
  A selected subset is explicit, and the remaining profiles are NOT_RUN.
- Each mapping names a bounded consumer obligation. No mapped detector means
  UNSUPPORTED_BY_THIS_COMMAND, never agreement or justified inapplicability.
- Preserve disagreements and UNKNOWNs together. Missing sources, unsupported
  source shapes, toolchain failures, timeouts or incomplete observations cannot
  produce an agreement. One successful profile cannot hide another failure.
- Execute actual committed target declarations. EA01 isolates Reports with the
  existing declared HtmlReport stub. EA03 extracts byte-identical runTest and its
  required declarations/dependencies. Record full source and projection hashes;
  neither method claims full-project or whole-CLI qualification.
- Use fixed independently evaluated fixtures with genuine positive controls,
  deliberate failures, repair and withdrawal. Reuse the already published
  L4YAML outcome repair c06ec22 as a candidate, without assuming its correctness.
- Existing 19-case XML and 8-case status methods remain independently visible.
  No inferred 104-item coverage percentage or global pass is emitted.

## Implementation and qualification

1. Import the authoritative catalogue and test complete, unique stable IDs.
2. Add independently scoped EA01 and EA03 adapters, fixtures and failure tests.
3. Add the local multi-profile runner, 104-row manifest and readable report.
4. Exercise all profiles without short-circuiting; validate result identities,
   missing/partial evidence, explicit exclusions and new-directory retention.
5. Freeze the method and qualify exact original/repair/withdrawal/unchanged and
   unavailable-source controls. Preserve raw observations, hashes and failures.
6. Review, publish a stacked draft PR, inspect Actions logs/artifacts and record
   the verified boundary in Research OS. No merge or upstream message.

## Remaining boundary

Four finite retained profiles are a first dispatcher, not 104 detectors. Other
Check capabilities and audited L4YAML repairs are not silently represented as
executed. Axiom admission, vacuity, numerics, runtime composition, general input
coverage and consequential value still require their own retained obligations.
