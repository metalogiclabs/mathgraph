## Preregistered V27 split-authority experimental mechanism

The owner-side high-water is a **separately signed fresh receipt**, held exclusively in the parent Go test process, returned by a read-only `httptest` HTTP owner service. The gateway subprocess gets only the owner's Ed25519 public key and a synthetic signed grant, not the owner private key. Each gateway process issues a freshly random **160-bit challenge nonce**; the parent owner signs version, nonce, OBSERVED phase and the exact full signed grant (scope, genesis, epoch, head/final hashes). A gateway verifies the pinned owner signature, challenge, exact subject and grant signature **before** checking any local journal or issuing native RPC. The owner floor changes only via a parent's `advance` method, which requires increasing epoch and exact current native head/final match. This is a two-domain protocol **in the test**, but all processes run under the same OS user; there is no production-grade credential isolation or persistent independent owner store.

The mutable gateway journal retains V25's fsync+rename+directory sync semantics. Gateway processes refuse a missing journal, a journal epoch lower than the owner-observed high-water, a journal higher than owner (in-doubt), a malformed journal, an unresolved PREPARED state, or an old signed grant. A recovery mode may rebuild journal state **only** after a fresh owner-signed observation and exact source-native `eth_getBlockByNumber(latest,finalized)` match. This test only warrants observing current native head/final, not establishing all historic effects.

## Four new native test roots

1. **Deleted journal, fail-closed and recovery.** With native B epoch2 Engine VALID, matching signed owner high-water B2, and a valid local journal2, delete only the gateway journal. An independently launched gateway process refuses old A epoch1. A second gateway process recovers the owner-observed B2 only after checking the actual native head/final. A third refuses signed old A. Another process executes genuinely signed epoch3 on the already-canonical B head with native Engine VALID, then parent owner advances its observed high-water. This must not claim native Geth reorg liveness.
2. **Rollback from observed epoch4 to valid journal2.** Parent owner advances signed high-water 2→3→4 for the already-canonical B head, with current native B head/final verified on every advance; gateway journal4 saved and then replaced by old signed journal2. New gateway subprocess refuses obsolete epoch3 because journal2 is behind independently signed owner4. Recovery with exact native B observation restores owner4, another subprocess rejects old epoch3, legitimate signed epoch5 proceeds with native Engine VALID. Note: epoch3/4 owner progress is owner-observed B state, **not** separately executed native Engine for each epoch.
3. **Forged / replayed owner observation.** A fake endpoint cannot produce a receipt matching the freshly random nonce signed under the pinned owner public key. Gateway refuses without native effect. Owner's controlled state API itself rejects backward epoch advances.
4. **Direct native bypass remains.** Parent sends authenticated raw Engine V4 A over the unfenced native API, genuinely rewrites canonical B→A. New gateway subprocess refuses to reconstruct owner-B journal because native head/final no longer matches. This **must remain a negative**; no complete effect mediation is claimed.

## Claims we must NOT promote

No durable owner anchor through *owner-process* crash; no owner-key anti-rollback when an attacker can change or reboot the independent source; no actual OS UID separation or authenticated private source of user authorization; no complete Engine mediation; no defense against source-provided pin replacement or local same-user compromise; no native Geth process restart; no multi-writer gateway serializability; no superiority to conventional equal-information control; no customer market validation. The synthetic V24 grant key is still a test fixture. This is NOT a production security patch or proof that Metatron autonomously discovered the source failure.

If bounded green, the next decisive experiment is an **owner-process restart** from an independently protected append-only/monotonic store plus a single mediated effect path, with independent adversarial revocation, and benchmark against an informed reference monitor. A signed, attacker-rewindable file cannot certify monotonicity.
