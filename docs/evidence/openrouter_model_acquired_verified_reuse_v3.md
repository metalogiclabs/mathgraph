# OpenRouter × MathGraph — Model-Acquired Verified Reuse V3

## Result

This is the first run in this series where the reusable capability bank itself
was generated by a real model rather than supplied in advance.

Configuration:

- model: `google/gemma-4-31b-it`
- route: OpenRouter → DeepInfra
- temperature: `0`
- seed: `0`
- acquisition tasks: 4
- untouched fresh tasks: 7
- acquisition retry cap: 3 independently checked attempts per task
- qualification run: https://github.com/metalogiclabs/mathgraph/actions/runs/35402116440

## Acquisition

Gemma proposed finite magma tables. MathGraph independently checked each proposal
before promotion.

| acquisition task | attempts | promoted |
| --- | ---: | --- |
| left projection → noncommutativity | 1 | yes |
| right projection → noncommutativity | 3 | no |
| commutativity → nonassociativity | 3 | no |
| commutativity → nonidempotence | 1 | yes |

So the model acquired **2 independently verified reusable capabilities** from 8
total acquisition calls. Rejected proposals stayed rejected.

Acquisition cost:

- model calls: **8**
- tokens: **1,206**
- OpenRouter cost: **$0.00012424**
- model latency: **8.44 s**

## Untouched fresh set

The seven fresh tasks were not used during acquisition. A single frozen
OpenRouter response was captured for each task as the paired cold fallback.

| condition | verified | reuse hits | model calls | tokens | OpenRouter cost |
| --- | ---: | ---: | ---: | ---: | ---: |
| cold | 7/7 | 0 | 7 | 971 | $0.00010849 |
| warm | 7/7 | 6 | 1 | 142 | $0.00001575 |
| restart | 7/7 | 6 | 1 | 142 | $0.00001575 |
| sham | 7/7 | 6 | 1 | 142 | $0.00001575 |
| ablation | 7/7 | 0 | 7 | 971 | $0.00010849 |

Fresh-set reduction from model-acquired verified reuse:

- **85.71% fewer model calls**;
- **85.38% fewer tokens**;
- **85.48% lower OpenRouter cost**;
- **90.49% less model latency**;
- exact terminal correctness preserved at **7/7**.

Targeted ablation restored the complete cold cost.

## Amortized sequence

The acquisition work is charged to both systems because both must solve the
acquisition tasks. The difference is whether verified outputs are retained and
compiled for later reuse.

Across acquisition + fresh tasks:

| | cold/no reuse | developmental reuse |
| --- | ---: | ---: |
| model calls | 15 | 9 |
| tokens | 2,177 | 1,348 |
| OpenRouter cost | $0.00023273 | $0.00013999 |

So even after paying the model-acquisition cost:

- **40.0% fewer model calls**;
- **38.08% fewer tokens**;
- **39.85% lower OpenRouter cost**.

## Sham-control limitation

The rotated-payload sham bank happened to contain mathematically valid tables
that independently solved the same six fresh tasks as the authorized bank.
Therefore the V3 sham condition is **not discriminative**: it ties warm rather
than falsifying it.

This does not invalidate the paired warm/cold or targeted-ablation result. The
checker correctly accepts any concrete artifact that solves the current task,
regardless of its label. But V3 should not be cited as evidence from the sham
control specifically.

The causal control that is informative here is targeted ablation: removing all
authorized capabilities that solve each fresh task restores 7 model calls, 971
tokens, and the cold cost exactly.

## Supported statement

On this bounded experiment:

> A real model generated mathematical artifacts; independent verification
> licensed two of them for promotion; after restart, those artifacts settled
> six of seven untouched related tasks without another model call.

That is a stronger developmental result than V2 because the useful state was
not preloaded.

## Claim boundary

This is still a small finite-magma fixture. It is not weight-level learning by
Gemma, not a claim about arbitrary mathematics, and not yet an experiment on the
official SAIR public problem distribution.

The next test should move this exact acquisition → verify → promote → restart →
reuse protocol onto pinned public SAIR Stage 2 problems.
